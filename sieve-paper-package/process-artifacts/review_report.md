# 审稿报告
**论文**：Sieve: Training-Free, Model-Free, Question-Conditioned Context Compression for Efficient Long-Context LLM Inference（NeurIPS 2025 双盲投稿）
**审稿人立场**：以 NeurIPS 评审标准评估；区分结构性缺陷与可修订缺陷；所有批评均落到可核查的表格、章节与数字。

---

## Part 1 [The Review Report]

### Summary
本文提出 Sieve——一个训练无关、模型无关的句子级上下文压缩器，以三个纯统计量（IDF 加权的查询覆盖度、U 形位置先验、预算内贪心 MMR 冗余惩罚）选句；核心主张是：在 QASPER + 生产级 LLM reader 上，4× 压缩的端到端 F1 与头截断"统计上不可区分"且高于全部问题无关选择器，证据召回在 r>2 的所有比率上超过全部基线（16× 处对截断有 2 倍优势），而压缩本身仅需 51.2 ms 单核 CPU、零模型参数——为"无神经打分器"这一设计空间角落给出首个系统量化。

### Strengths

1. **定位到真实的设计空间空缺，并贡献了一个可复用的评测协议。** "model-free 压缩器"这一角落此前确实无人系统量化（LLMLingua 系、Selective Context 均需托管神经打分器）。论文提出的 reader-free 证据召回协议把压缩质量从特定 reader 的耦合中解耦出来，可用置信区间分离、零 API 成本、可大规模运行——这对压缩社区是有普遍价值的方法学贡献，独立于 Sieve 本身是否被采用。

2. **罕见的报表诚实度与可复核性。** 论文主动披露端到端指标上截断反超 2.1 F1（4.2 节）、主动披露位置先验损害召回（Table 3：0.416→0.442）、成本对比刻意取神经压缩器的最优下界、Limitations 覆盖面超出常规（明确承认端到端消融与 reader 侧放置研究是 future work）。我独立复核了 Table 4 的全部解析计算：LLaMA-2 7B（32层×32 KV头×128维→8k token bf16 = 4.29 GB，论文 4.2）、13B（6.71 GB，论文 6.6）、70B（GQA 8 KV 头→2.68 GB，论文 2.6），以及 2·N·L FLOPs 在 40% MFU A100 下的 prefill 时延（0.92/1.71/9.19 s，论文 0.86/1.67/8.8）——全部自洽；Table 1 的 Retain（18.6/32.1=57.9%）与 ΔF1 亦核对无误。这种算术可复核性在投稿中并不常见。

3. **召回-比率扫描与放置分析产出了有信息量的发现。** Fig. 1 揭示截断在预算收紧时坍塌、问题条件化选择退化缓慢的交叉规律；Fig. 2 显示选择器层面的 U 形先验以 0.087 的中部召回率复现了 reader 的 lost-in-the-middle 剖面（0.957 起始 / 0.979 末端），并给出 floor 参数对该权衡的显式控制——这对从业者有具体指导价值，是全文最有 instructive 价值的分析。

### Weaknesses (Critical)

**W1. 端到端评测的统计功效不足以支撑任何比较性结论，且推断程序本身无效。**
主表 n=25：Full context EM 20.0 即 5/25 答对，Sieve 8.0 即 2/25——EM 上 1 道题=4 个百分点。论文以"bootstrap 区间几乎完全重叠"宣布 Sieve 与截断"统计上不可区分"（4.2 节），但**重叠的边际 CI 不能用于推断无差异**；正确做法是对同一批 25 题报告 ΔF1(Sieve−Head) 的配对 bootstrap / 置换检验区间。按现有程序，"statistically indistinguishable" 是无效推断；同理，摘要中 "lying above every question-agnostic selector"（18.6 vs 15.6 F1，n=25）未经任何显著性检验。现有证据下，全文的端到端比较性陈述（包括持平声明与"高于"声明）均无统计支撑。

**W2. 承重实验缺失：论文最强的主张从未被连接到端到端指标。**
全文卖点是召回优势随压缩率扩大（4× 处 5 个点 → 16× 处 2 倍），但端到端实验只做了 r=4 一个工作点，r=8/16 处没有一行 QA 精度数据。4.2 节的过渡句明言价值"shows up... at higher compression ratios, which subsection 4.3 measures"——而 4.3 测量的是召回代理指标，不是端到端精度。换言之，"更高证据召回 → 更好 QA"这一核心价值链条完全未经检验；在唯一测过的工作点（4×）上，端到端结论是负的（-2.1 F1）。摘要把"端到端持平"与"召回优势随比率增长"并置，读者会自然合成出一个从未被实验支持的命题。

**W3. 缺失与神经压缩器的精度对比，且给出的理由不成立。**
论文的中心问题是"无模型压缩器在精度上付出多少代价"（"quantifies what it costs in accuracy"，2 节），但 LLMLingua / LongLLMLingua / LLMLingua-2 / Selective Context 一个都没有运行，理由是"cannot be run in our setting without hosting a scorer"（4.1 节）。这一理由混淆了**部署约束**（论文的动机）与**评测约束**（实验的可行性）：作者拥有 8 vCPU 容器，LLMLingua-2 的 117M 分类器完全可在 CPU 上推理；评测侧运行神经基线不损害"部署时无需托管"的论点。现状是：成本维度的对比是解析的（公平且诚实），精度维度的对比——恰恰是论文自称要量化的东西——完全缺席。LongLLMLingua 同为 question-conditioned，是最直接的概念对手，绕开它使"空缺角落"的论证不完整。

**W4. 消融结果与"三组件"设计叙事相互拆台，且权衡的收益端从未在端到端层面验证。**
Table 3 显示：去掉问题条件化，召回从 0.416 跌到 0.314（价值的几乎全部来源）；把位置先验拍平，召回**反升**到 0.442（先验在论文自己的主指标上是有害项）；冗余惩罚贡献 0.011（可忽略）。消融矩阵中缺一个 relevance-only 配置（α=1, flat prior, β=0）——即最自然的 BM25 式选句基线，导致"问题条件化"与"其余设计"的贡献无法分离。更关键的是 U 形先验的辩护逻辑：其全部理由（"把可靠性预算花在 reader 可靠的位置"）依赖 reader 端的 U 形剖面，但论文承认 "a reader-side placement study under our own reader remain future work"（第 5 节）——先验建立在 Liu et al. 在**其他模型**上报告的现象之上，在本 reader（GLM-4-Plus、约 5k token）上从未验证；唯一能显示该权衡收益的端到端消融（flat prior 的 F1）也没有做。4.6 节标题 "the selector mirrors the reader" 是一个类比，不是测量。综合来看：三个组件中只有一个承重，方法命名与章节结构所暗示的设计完整性未被实验支持。

**W5. 评测账目存在多处不自洽，其中两处涉及承诺-兑现缺口。**
(a) Appendix B 报告 dev F1 = 52.6（α=0.3），而同一配置的 test F1 = 18.6——**34 分的 dev-test 差距无任何解释**；dev 集由 10 条 QASPER + 10 条 HotpotQA 构成，分布与测试集严重不同，基于它的 α 选择本质无效（作者自己承认三点差异 "within the noise"），但 3.4 节又称该选择被 dev-split agreement "支持"。
(b) 3.4 节承诺 "Sensitivity to all four values is reported in Appendix B"，但 Appendix B 只含 α 的 3 点网格，**β、floor、γ 的敏感性分析并不存在**——承诺内容缺失；checklist 第 1 条"claims alignment = Yes"因此不能成立。
(c) 44 条召回记录与 25 条测试 + 20 条 dev（其中仅 10 条 QASPER）采样记录的关系未说明——若召回池含用于调参的 dev 记录，Table 2/3 存在调参污染；放置分析又报 "n up to 48 per position"，与 44 对不上——各分析的记录池账目不一致。
(d) reader-free 协议零 API 成本，却没有理由地自我限制在 n=44——QASPER train 有数千条问题，召回曲线本可跑数百条记录换窄区间，这是对自家协议优势的浪费。

**W6. 覆盖面：单基准、单 reader、端到端仅单工作点。**
端到端证据全集 = QASPER × GLM-4-Plus × r=4；HotpotQA 只进了 dev（10 条）从未做端到端评测；无第二个 reader 家族（API reader 的版本漂移虽有 checkpoint 缓解，但结论对模型家族的一般性为零）。对"how far can a compressor go with no neural network"这一普适性提问而言，这不是表述问题，是证据密度问题。

**次要问题**（不改变评分量级，但应在修订中清理）：4.1 节交叉引用错乱（"Sections 4.4–4.3"）；checklist 第 1 条含损坏引用"？?"；Table 4 caption 定义了 API 成本口径（$3 / $0.5 per M tokens）但表中并无该列；摘要 "retains strictly more gold evidence than all baselines" 在 4× 处对截断的 CI 完全重叠（[0.301, 0.534] vs [0.227, 0.500]），"strictly more" 只是点估计措辞，正文 4.3 的显著性声明也只覆盖问题无关基线、刻意不含截断——摘要与正文的精度不对齐。

### Rating

**4 / 10（Borderline Reject，倾向拒稿）。**
方法有效、算术可复核、报表诚实，但支撑其主张的经验内核——n=25 的端到端比较、无效的统计推断程序、缺失的神经基线与端到端消融、以及从未在端到端层面检验的高压缩率卖点——远低于 NeurIPS 的证据门槛；补齐应做实验后其上限约为 6 分（solid borderline accept），当前版本低于接收线。

## Part 2 [Strategic Advice]

### 问题根源

- **W1/W6 的根源是实验预算设计，而非方法缺陷。** 全部评测只消耗了 256 次 API 调用（Appendix C）——论文为压缩成本而生的节俭被错误地复制到了评测预算上；n=25 的宽区间随即被"indistinguishable"的修辞利用，让一个功效不足的实验看起来像一次合格的持平检验。方法本身（公式、复杂度、成本测量）经复核没有错误。
- **W2 的根源是一次未被承认的代理替换。** 论文最强的结果住在召回代理指标里；把 r=8/16 的端到端跑出来存在"召回优势不转化为 F1"的真实风险——当前的范围选择（无论有意与否）回避了这一检验，并用 4.2 节的交叉引用把读者引向代理指标。"更高召回 ⇒ 更好 QA"在 QASPER 这种多跳、多证据句的任务上并非显然成立（部分证据集可能丧失推理所需的连贯性）。
- **W3 的根源是身份叙事对实验设计的越权。** "我们不能托管打分器"是部署约束（卖点），却被用作评测约束（借口）；两者在逻辑上完全可以分离——为评测租一张 GPU 并不削弱"目标场景无法托管"的动机。
- **W4 的根源是先验设计遭遇了否定性消融结果后的叙事修补。** 三组件设计是 a priori 的；Table 3 揭示两个组件不承重（先验有害、冗余可忽略）后，论文把先验的伤害重新包装为"deliberate trade-off"，而该权衡的收益端（reader 可靠性）没有对应测量——这是**表述在为方法补位**，不是方法本身失效；flat prior 版本（可能召回和 F1 双优）才是消融暗示的更强配置。
- **W5 的根源是小规模实验的账目纪律松弛**，叠加 dev 集混入异分布数据（HotpotQA）却未讨论其后果。

### 可救性判断

**修订期内可完全解决（均为低成本）：**
- W1：端到端扩到 n≥300（约 2000 次 API 调用、数小时）；改用配对 bootstrap 报告 ΔF1 区间——纯分析重写，无需新方法。
- W2：补 r∈{8, 16} 端到端扫描（6 条件 × 300 例，一天内可完成）。
- W3：LLMLingua-2 可在现有 8 vCPU 容器上推理；LongLLMLingua 租单卡即可；两者共享同一 split/reader/预算。
- W4 的实验部分：补 relevance-only 消融行、flat-prior 的端到端 F1、自家 reader 的 U 形剖面验证（在 5k token 合成放置上测 GLM-4-Plus 即可）。
- W5：补 Appendix B 的 β/floor/γ 网格（纯本地计算，无 API 成本）；给出 44 条记录池的构成表；召回协议扩到全量过滤后的 QASPER train（数百条）。

**结构性、修订无法解决：**
- **方法新颖度天花板。** MMR（1998）、IDF 加权（经典 IR）、位置先验（lost-in-the-middle 的直接转译）均为成熟组件；论文的贡献上限是"强 model-free 基线 + 评测协议 + 诚实的成本核算"，不是新方法。这不是缺陷，但决定了即使全部实验补齐，论文的天花板约在 6 分档，除非神经基线对比揭示出意外有利的结果。
- **核心结果的不可预知性。** 若 W2 的补测显示召回优势不转化为端到端优势，论文只能重定位为测量协议论文——这是实验结果问题，任何写作技巧无法挽回。
- **U 形先验的存废风险。** 若端到端消融显示 flat prior ≥ U 形先验（召回已高 2.6 个点，F1 未必更差），方法的标志性组件失去存在理由，"三统计量"叙事坍缩为"BM25 + 预算贪心"。

### 行动指南

1. **先做决定论文命运的单一实验**：r∈{2, 4, 8, 16} × n≥300 的端到端扫描，报告 ΔF1(Sieve−Head) 的配对 bootstrap 95% CI。若 r≥8 处 F1 显著占优——论文获得真正的故事（"model-free 在压缩最痛的地方获胜"）；若不占优——趁早重定位为协议/基线论文，不要让摘要继续暗示一个不存在的胜利。
2. **补神经基线并画出论文应得的那张图**：LLMLingua-2（CPU）+ LongLLMLingua（单卡租用），同一 split、同一 reader、同一预算，横轴为压缩侧成本（ms / 参数量），纵轴为 F1 的 Pareto 散点图。这张图一旦画出来，"空缺角落"的论证才算闭合；目前的解析成本下界对比只能回答成本问题，回答不了精度问题。
3. **reader-free 协议扩到全量**：召回曲线跑数百条过滤后 QASPER train 记录；补 relevance-only（BM25 式）与 α 网格消融行；补 flat-prior 端到端 F1。这一步零 API 成本、几小时完成，是性价比最高的修订。
4. **第二基准 + 第二 reader**：HotpotQA 端到端（数据已在手）；本地开权重模型（Llama-3 / Qwen 任一）作为第二 reader，同时在其上完成 U 形剖面验证——先证明自家 reader 确有该现象，再让先验依赖它。
5. **账目与写作修复清单**：修复 4.1 交叉引用与 checklist 的"？?"；Table 4 补 API 成本列或从 caption 删除该口径；在 Appendix B 解释 dev/test 34 分差距（给出 dev 集构成与逐题难度）；摘要把 "strictly more gold evidence" 限定为点估计并标注 4× 处与截断的 CI 重叠；全文以配对检验替代"CI 重叠 ⇒ 不可区分"的论证方式。
6. **Rebuttal 攻击面压缩（若实验来不及）**：(a) 摘要主动坦白 4× 端到端是与截断**持平**而非获胜——现在的措辞（"indistinguishable... while lying above"）可被读成获胜，这是最容易被 AC/其他审稿人放大的点；(b) 对"为何无神经基线"给出双轨回应：保留部署约束叙事 + 承诺 camera-ready 前补 LLMLingua-2 CPU 结果；(c) 附上补全的 Appendix B 敏感性网格（纯本地计算）以直接关闭 W5(b)；(d) 用一段话澄清 44 条记录池与 dev 的关系；(e) 绝不辩护"CI 重叠 ⇒ 无差异"——直接改为配对区间并更新结论措辞。

**审稿人自查记录**：
1. 每条 Weakness 均落到具体表格（Table 1/2/3/4、Fig. 1/2）、章节（3.4/4.1/4.2/4.3/4.6/5、Appendix B/C、checklist 第 1 条）与数字（-2.1 F1、0.416→0.442、52.6 vs 18.6、n=25/44/48、CI 重叠区间），可逐项操作。
2. 已区分方法缺陷与证据/表述缺陷：方法公式、复杂度声明、成本测量与 Table 4 算术经独立复核无误，全部批评指向评测规模、推断程序、承诺-兑现缺口与叙事越位；W4 被明确标注为"表述为方法补位"而非方法失效。
3. 评分依据：论文无方法硬伤、报表诚实（高于纯拒稿档 2-3 分），但主张所需证据密度显著低于现有实验（低于接收线 6 分）；经验内核补齐后上限约 6 分，故评 4 分——反映实际水平而非预设严苛。
